# 食事管理アプリ（APP-2）

生活管理アプリ（APP-1・ハブ）とは別プロジェクトとして動く、食事・体重の記録＆栄養評価アプリです。
[`02_要件定義書_食事管理アプリ.md`](../02_要件定義書_食事管理アプリ.md) の要件（F-04〜F-07）に対応します。

## 前提

- ハブと**同じ MariaDB インスタンス・同じ `life_manager` データベース・同じ `users` テーブル**を共有します
  （[`00_システム全体構成・連携仕様.md`](../00_システム全体構成・連携仕様.md) 3章の合意）。
- そのため、ハブ側のスキーマ（`../db/01_schema.sql` 〜 `../db/04_multiuser.sql`）が先に適用済みであることが前提です。
- Node.js 18 以上（`fetch` をグローバル関数として使用しています）。

## セットアップ

```bash
cd meal-app
npm install
cp .env.example .env   # DB接続情報はハブと同じ life_manager DBを指す
npm run dev
```

初回のみ、このアプリ独自のテーブル（`meal_logs` / `weight_logs` / `nutrition_targets` / `hub_connections`）を
ハブと同じ DB に作成します。

```bash
mysql -u root -p life_manager < db/01_schema.sql
```

デフォルトでは `http://localhost:3001` で起動します（ハブは `3000`）。
ログインは**ハブ側に登録済みのアカウント**でのみ行えます（このアプリに新規登録機能はありません）。

## ハブとの連携

1. ハブ（`http://localhost:3000`）にログインし、設定画面で「食事管理アプリ」の認証トークンを発行する
2. このアプリの設定画面（⚙️）にトークンを貼り付けて「連携する」を押す
3. 以降、食事・体重の記録を追加・編集・削除するたびに、その日の要約（grade・badge・metrics 最大6件）が
   ハブの `content_summary_cache` に自動で書き込まれる（F-07-01/02）

## 画面（6画面・要件定義書 第3章）

| ID | 画面 | 概要 |
| --- | --- | --- |
| A2-01 | 当日サマリー | `#/summary` |

## 実装メモ・未確定事項

- **採点ロジック（F-06）**：目標カロリーとの達成率の差（%）で S/A/B/C を判定する暫定ロジックを
  [`server/grading.js`](server/grading.js) に実装した。閾値（5/15/30%）は仮の値。要件定義書 7章に
  「実装時にユーザーと合意する」とある通り、実データで運用しながら調整が必要。
- **食品データベース連携**：本フェーズでは行わず、食品名はフリーテキスト入力（F-04-02の想定通り）。
- 論理削除・日付の扱い・金額（カロリー等）を整数で持つ方針はハブのスキーマ規約に揃えた。
