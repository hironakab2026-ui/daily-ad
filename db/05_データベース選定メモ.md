## 1. 本当の分岐点は「オフライン対応の要否」

データベース製品の選択より先に、これを決める必要がある。ここで難易度が一桁変わる。

要件定義書 C-05〜C-06 では「オフラインでも全ての記録操作が可能」と定めた。これを守るには端末側とサーバー側の両方にデータベースを置き、**同期させる**必要がある。同期の自作は本プロジェクトで最も難しい部分になる。

逆に「通信できないときは記録できなくてよい」と割り切れば、サーバーありのほうが**むしろ単純**になる。データベースが1つしかないので、同期も競合解決も存在しない。

---

## 2. 3つの構成

| 案 | 構成 | オフライン | 難易度 | 向いている状況 |
| --- | --- | --- | --- | --- |
| **A** | SQLite のみ（端末内） | ○ | 低 | まず動くものを作りたい。学習の初手 |
| **B** | サーバーDB のみ | **×** | 低〜中 | Webアプリとして作る。サーバーを学びたい |
| **C** | SQLite ＋ サーバーDB ＋ 同期 | ○ | **高** | 要件定義書どおり。最終形 |

> **A → C、B → C のどちらの移行も可能。** ただし B → C は端末側DBを新設することになるため、データ層の作り直しが発生する。

### 判断材料
- 買い物直後のレシート入力を想定している。**外出先で通信できない場面がどれだけあるか**が案Bの可否を決める
- 学習目的が主なら、案A または案B から始めて C は後回しにするのが現実的

## 3. データベース製品の比較

| | SQLite | MariaDB | PostgreSQL |
| --- | --- | --- | --- |
| 形態 | ファイル1個 | サーバー | サーバー |
| 導入の手間 | ほぼなし | 中 | 中 |
| 端末内DBとして | ◎ | × | × |
| サーバーDBとして | △ | ○ | ○ |
| **日本の安価なレンタルサーバー** | − | **◎ 標準採用** | △ 使えないことが多い |
| ウィンドウ関数・CTE | ○ | ○（10.2以降） | ○ |
| CHECK 制約 | ○ | ○（10.2.1以降） | ○ |
| 部分インデックス | ○ | **×** | ○ |
| JSON 型 | △（文字列） | △（実体は LONGTEXT） | **◎ jsonb** |
| 日付型 | **×（文字列で代用）** | ○ | ○ |
| 学習の汎用性 | 低 | **高（MySQL系は求人・既存システムで広く通用）** | 高 |

### 本プロジェクトでの実質的な差

**Phase 1（収支・タスク）では差がほぼない。** 3つとも要件を完全に満たせる。

差が出るのは以下のみ。

| 箇所 | 影響 |
| --- | --- |
| `content_summary_cache.metrics`（コンテンツ要約のJSON） | PostgreSQL の jsonb なら中身で検索できる。MariaDB / SQLite は文字列として出し入れするだけ。**Phase 3 以降の話で、しかも検索の必要性は低い** |
| 論理削除の部分インデックス | MariaDB は非対応。通常のインデックスで代替でき、この規模では体感差なし |
| 日付の扱い | SQLite のみ文字列で代用。`'YYYY-MM-DD'` 形式なら文字列比較が日付比較として機能するため実害はない |

## 4. 推奨

### 学習を主目的とする場合
**MariaDB（案B）** を推奨する。理由は以下。

1. **サーバー構成を一通り学べる。** 接続、権限、バックアップ、マイグレーションといった、SQLite では触れない領域が含まれる
2. **MySQL 系の知識は応用が利く。** 既存システムでの採用率が高く、学んだことが他所で使える
3. **将来のホスティング先が多い。** 日本の安価な共用サーバーで動かせる
4. **オフライン同期という最難関を後回しにできる**

### 置き場所
まずは**自分の PC に立てる**。クラウドの契約は不要。

| 方法 | 手間 | 備考 |
| --- | --- | --- |
| 公式インストーラ | 小 | Windows / Mac ともに GUI で完結。**初学者はこちら** |
| Docker | 中 | 環境を汚さない。Docker 自体の学習が先に必要 |
| XAMPP / MAMP | 小 | Web サーバーもまとめて入る。Web アプリを作るなら楽 |

公開したくなった段階でクラウドや レンタルサーバーへ移す。書いた SQL はほぼそのまま動く。

### それでも案A（SQLite）が向く場合
- とにかく早く動くものを見たい
- 環境構築で躓きたくない
- オフライン対応を最初から確保したい

## 6. PostgreSQL を選ぶ場合の変換点

MariaDB 版から PostgreSQL へ移す場合、主な差分は以下。

| 箇所 | MariaDB | PostgreSQL |
| --- | --- | --- |
| 連番 | `AUTO_INCREMENT` | `GENERATED ALWAYS AS IDENTITY` |
| 重複無視の INSERT | `INSERT IGNORE` | `INSERT ... ON CONFLICT DO NOTHING` |
| 曜日の取得 | `DAYOFWEEK(d)`（1=日） | `EXTRACT(DOW FROM d)`（0=日） |
| 日の取得 | `DAY(d)` | `EXTRACT(DAY FROM d)` |
| 現在時刻 | `NOW()` | `NOW()`（同じ） |
| 文字列連結 | `CONCAT(a,b)` | `a \|\| b` |
| JSON | `LONGTEXT` 相当 | `jsonb`（推奨） |
